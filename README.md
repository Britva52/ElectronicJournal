# Учебный портал СПО

Django-приложение: новости, расписание, библиотека ссылок, личный кабинет и электронный журнал. Учебные группы, предметы, пользователи, занятия, новости и материалы создаются через админ-панель. Занятия используются одновременно в расписании и журнале.

## Запуск для разработки

Нужен Python 3.10 или новее (Django 5.2).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Откройте http://127.0.0.1:8000/; панель управления — `/admin/`. В существующем окружении используйте отдельное виртуальное окружение, если `.venv` создан на другом компьютере.

Создайте группы и предметы, пользователей и профили студентов (с указанием группы), затем занятия. Время и аудитория у занятия необязательны. Новости и материалы появляются на сайте только после включения флага «Опубликовано»; будущие новости отображаются после даты публикации. Библиотека пока хранит ссылки, а не загружаемые файлы.

Студент видит расписание и журнал своей группы, преподаватель — свои предстоящие занятия и может редактировать отметки только на своих занятиях. Преподаватели могут просматривать другие группы, но для замены требуется изменить преподавателя занятия через админ-панель. Роль администратора журнала задаётся отдельно от флагов доступа к админ-панели Django (`is_staff`/`is_superuser`); для управления данными нужны соответствующие права Django.

Тесты: `python manage.py test`.

## Перед реальным внедрением

Это учебная основа, не готовый к публикации сервис: настройки DEBUG и SECRET_KEY предназначены только для разработки. Потребуются защищённые настройки и секреты из окружения, HTTPS, резервное копирование, аудит изменений, согласование доступа к персональным данным, политика хранения и восстановления, управление заменами, а также проверка инфраструктуры и безопасности. SQLite и публичная база из репозитория не подходят для эксплуатации с реальными персональными данными. В интерфейсе используется Bootstrap через внешний CDN.

## История оценок и проверки

Изменения отметок через журнал сохраняются в разделе «История изменений оценок» админ-панели: автор, студент, занятие, прежнее и новое значение. Сохранение без изменения повторной записи не создаёт. Разделы оценок и их истории в админ-панели доступны только для просмотра; изменяйте оценки через журнал. История начинается с момента установки этой версии и не восстанавливает предыдущие изменения. Действия через админ-панель дополнительно фиксируются в журнале действий Django; прямые изменения базы не журналируются, поэтому это ещё не полноценный аудит для эксплуатации.

В формах админ-панели проверяются роль студента и преподавателя, порядок времени занятия и корректность оценки. Проверки моделей действуют при вызове `full_clean()` и в формах, но не выполняются автоматически при прямом `save()` или массовых изменениях через ORM. Перед эксплуатацией также нужно дополнить учёт переводов датами обучения и правилами исправления архивных отметок.

## Переводы и удаление

Меняйте группу в профиле студента через админ-панель. Перевод фиксируется в разделе «История переводов студентов», а оценки остаются в журнале прежней группы: переведённый студент показан там только при наличии оценок, и эти отметки доступны только для просмотра. В новой группе показывается текущий состав. После перевода доступ студента к прежней группе закрыт. Переводы до появления этой функции не восстанавливаются; даты обучения и возможность исправления старых отметок пока не реализованы.

Занятия и профили студентов с оценками защищены от удаления через Django ORM, включая каскадное удаление; группу занятия с оценками нельзя поменять в форме. Обычные действия в админ-панели, в том числе удаление, можно посмотреть в её журнале действий (доступен суперпользователю). Это не полный аудит: прямые изменения базы или ORM в обход админки и удаление связанных объектов каскадом не фиксируются по отдельности. Журнал действий хранится в той же базе и не защищён от администратора базы. Для реальной эксплуатации необходимы независимое неизменяемое хранилище аудита, политики удаления и хранения персональных данных и проверка прав.

## Данные для демонстрации

Команда `seed_demo` создаёт вымышленные новости, материалы, занятия и пользователей, включая суперпользователя. Используйте **только отдельную тестовую базу**: команда добавляет данные в настроенную базу, не удаляет их и не предназначена для производственной среды. Она откажется работать, если демо-логины уже существуют. Задайте временный пароль через переменную окружения и подтвердите использование тестовой базы:

```bash
# Linux/macOS (на Windows задайте переменную окружения соответствующим способом)
export DEMO_PASSWORD='временный-пароль-для-демо'
python manage.py seed_demo --confirm-demo-database
```

Логины: `demo_admin` (суперпользователь и администратор журнала), `demo_teacher` (преподаватель) и `demo_student` (студент). Все используют заданный `DEMO_PASSWORD`. Не публикуйте тестовую базу и тестовый пароль вместе с реальными данными.

### Встроенный предпросмотр Arena

`config.preview` — отдельные настройки только для HTTPS-предпросмотра: отдельная база `PORTAL_PREVIEW_DB`, доверенный домен предпросмотра и защищённые cookies с `SameSite=None`. В обычном локальном запуске используйте `config.settings`. Если браузер блокирует сторонние cookies во встроенном окне, откройте предпросмотр в отдельной вкладке и заново загрузите страницу входа. Отключать CSRF-защиту не требуется. Эти настройки не являются настройками для промышленного развёртывания.

### Локальный демонстрационный режим

Если вход во встроенном окне Arena не работает из-за ограничений cookies, запустите отдельную демобазу на своём компьютере. Команды ниже не изменяют `db.sqlite3`; создаётся `demo.sqlite3`. Сначала установите зависимости, как описано выше.

Windows PowerShell:

```powershell
python manage.py migrate --settings=config.demo
$env:DEMO_PASSWORD = 'Demo2026!'
python manage.py seed_demo --confirm-demo-database --settings=config.demo
python manage.py runserver --settings=config.demo
```

Linux/macOS:

```bash
python manage.py migrate --settings=config.demo
DEMO_PASSWORD='Demo2026!' python manage.py seed_demo --confirm-demo-database --settings=config.demo
python manage.py runserver --settings=config.demo
```

Откройте http://127.0.0.1:8000/accounts/login/. Логины: `demo_student`, `demo_teacher`, `demo_admin`, пароль — заданное значение `DEMO_PASSWORD`. Команду `seed_demo` запускайте один раз: она не перезаписывает существующих демопользователей. Эта база и демопароли предназначены только для локальной проверки.

### Пример недельного расписания

В локальной демобазе можно добавить группы `о-П-923/1`, `о-П-923/2`, `о-П-923/3`, `о-Э-923/1`, `о-Э-923/2`, `о-Э-923/3`, `о-П-1124` и пример дополнительной группы `о-П-924/1`. Группы без исходного расписания остаются пустыми. Для групп `о-П-923/3` и `о-П-1124` создаётся **пример одной недели** по присланному изображению. Даты и преподаватель демонстрационные, названия, аудитории и время требуют проверки; не используйте этот пример как официальное расписание. Он не повторяется автоматически каждую неделю.

После установки зависимостей и `migrate --settings=config.demo` в PowerShell выполните:

```powershell
$env:DEMO_PASSWORD = 'Demo2026!'
python manage.py seed_example_schedule --settings=config.demo
python manage.py runserver --settings=config.demo
```

Чтобы проверить расписание студента, войдите как `demo_923_student` с этим паролем; для проверки преподавателя — `demo_schedule_teacher`. Эти учётные записи создаются указанной командой. У администратора есть фильтр групп. Если вы уже запускали `seed_demo`, это отдельная команда, её можно выполнить без повторного запуска `seed_demo`. Она не перезаписывает существующих пользователей и может выполняться только один раз; задайте `--week 2026-10-26`, чтобы выбрать неделю при первом заполнении. Занятия в демобазе можно затем исправить через админ-панель. При запуске без параметра используется текущая неделя компьютера.
